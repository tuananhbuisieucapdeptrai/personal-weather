### 0.2.1 Sketch ↔ Linux

**Transport (proposed; Minh confirms at M1.1).** The Bridge is RPC, so the sketch uses typed arguments rather than a JSON parser. `bridge_io.py` converts between Bridge calls and the contract dicts:

| Contract dict | Bridge call |
|---|---|
| `{"t", "rh"}` | sketch: `Bridge.notify("env", t, rh)` |
| `{"knob": "turn", "pos"}` | sketch: `Bridge.notify("knob_turn", pos)` |
| `{"knob": "press"}` | sketch: `Bridge.notify("knob_press")` |
| `{"face": name}` | python: `Bridge.notify("face", name)` → sketch: `Bridge.provide_safe("face", ...)` |
| `{"face": "feedback", "pos"}` | python: `Bridge.notify("face_feedback", pos)` → sketch: `provide_safe` |
| `{"face": "text", "text"}` | python: `Bridge.notify("face_text", text)` → sketch: `provide_safe` |
| `{"beep": name}` | python: `Bridge.notify("beep", name)` → sketch: `provide_safe` |

Bridge rules for this design (see `docs/kickoff-guide.md`):
- Use `notify` in both directions. `notify` doesn't wait for an answer, so `bridge_io.send()` never blocks.
- The sketch registers its handlers with `provide_safe`, because they touch the LED matrix and buzzer.
- The sketch's `loop()` must never call `delay()`, because `provide_safe` handlers only run between passes of `loop()`.
- Python Bridge handlers must not call `Bridge.call()`. They only put the message on a queue.
- Each message is limited to 256 bytes.

**Environment**
- Sent once per second. Values are raw, in °C and %RH, with one decimal.
- A failed sensor read sends nothing; the sketch never sends NaN. If Linux hears nothing for more than 5 s, it marks the sensor as stale.
- Smoothing happens in Python, so it can be tested with mocks.
- The Thermo is mounted outside the case.

**Knob**
- The sketch keeps the position clamped to **−1 / 0 / +1**, with one detent per step. It sends `turn` only when the position changes.
- After a `press`, the sketch resets the position to **0** without sending a message. Linux assumes the position is 0 after every press.
- Position meaning depends on what Linux is showing:

| pos | Feedback (C4) | Responding to a suggestion (C6) |
|---|---|---|
| −1 | cold (arrow left) | **NO**: "Not possible for me" (recorded as a constraint, no penalty) |
| 0 | OK (dot) | **LATER**: "Not now" (no penalty; the default) |
| +1 | warm (arrow right) | **DO**: "Do it" (starts the follow-up) |

- The click sound on each detent is played by the sketch itself, with no message. `beep` has no `click` value.

**Faces** (each face stays until the next `face` message)

| face | Shows | Typically sent with |
|---|---|---|
| `smile` / `sun` / `snow` | comfort OK / warm / cold | — |
| `suggest_layer_on` / `suggest_layer_off` | fix icon. The sketch makes it blink. | `{"beep": "chime"}` |
| `text` + `text` | scrolling text: only `DO`, `NO`, `LATER` for now; at most 8 characters of A–Z, 0–9 and space | — |
| `feedback` + `pos` | arrow left / dot / arrow right | — |
| `check` | check mark after a confirm | `{"beep": "chirp"}` |
| `eye_off` | crossed-out eye for ~3 s, then the sketch switches to a corner dot by itself | `{"beep": "low"}` |
| `off` | matrix blank | — |

Linux decides every sound except the click. The sketch never beeps by itself.

### 0.2.2 vision.py → main.py

- `clothing`: `outer` matches the spec's `outer_layer`, `none` matches `no_outer_layer`, and `uncertain` covers everything else.
- The stability filter runs inside vision. A state is accepted only after several consistent frames.
- `camera == "on"`: `present` is true or false. If nobody is present, `clothing` is `"uncertain"` and `conf` is null. A clothing decision (`outer` or `none`) always comes with a `conf` value.
- `camera == "off"` or `"shutter"`: vision knows nothing, so the dict is `{"present": null, "clothing": "uncertain", "conf": null, "camera": ...}`. `main.py` then falls back to knob activity or the dashboard.
- `"shutter"`: after ~3 s of almost completely dark frames, vision stops capturing by itself. It does not resume on its own; someone has to open the shutter and press "camera on" on the dashboard. The privacy receipt can then truthfully say "no capture while the shutter is closed".
- Images exist only in memory. They are never written to disk and never sent.

### 0.2.3 Device local API (port 8000, local only, labelled debug)

- **`POST /control`**: JSON with any non-empty subset of these fields:
  - `"profile"`: `"tuananh"` or `"minh"`
  - `"camera"`: `"on"` or `"off"`
  - `"mode"`: `"heating"`, `"cooling"` or `"unknown"`. The default is **heating**.
  - `"reset_pid"`: `true`
  - `"clothing"`: `"outer"`, `"none"` or `"auto"`. `auto` means the camera decides. This is the dashboard fallback from the 14:00 gate.
  - The response is the new `/state`. An invalid body returns 400 with the contract error.
- **`GET /state`**: a snapshot for the dashboard, owned by Tuan Anh. Its shape is **not frozen**. It covers live t/rh, vision, active profile, mode, per-profile predictions/offset/band, suggestion status, evidence-panel numbers, fix experience, the last summary sent, and an `inputs` field (`"live"` or `"mock"`).

### 0.2.4 Device → hub (spec C8)

- `POST http://<hub>:8080/summary` with exactly the C8 body. The hub replies 204.
- **One summary per profile.** Only the active profile can have `present: true`, because one desk means one person.
- Sent every **60 s as a heartbeat**, and immediately when any field changes.
- The hub stamps **receipt time** and ignores device clocks. A summary older than **2 min** is stale, and that person is treated as absent.
- `pid`: `"p-"` + 4 random hex characters. It is persistent per profile and stored on the device. `reset_pid` replaces it. It is never a name.
- `band_now` / `band_with_fix`: `[low, high]` in °C with one decimal, or `null` if no temperature in the search range is OK. Omit `band_with_fix` when no feasible fix exists, including after "Not possible".
- `state`: the person's current comfort class (−1/0/+1).
- `unresolved`: true while the person is uncomfortable and has no feasible fix.
